# 校园文创限时抢购系统分阶段开发计划

> 本计划依据 [需求规格说明书](requirements.md) 制定，采用“基础设施 → MVP 主链路 → 高并发增强 → 运营治理 → 测试部署”的迭代方式。每项任务均包含交付物和验收标准。

------

## 1. 开发计划概览

### 1.1 时间线

| 阶段 | 周期 | 目标 |
| :--- | :--- | :--- |
| Phase 0 基础设施 | Week 1 | 项目骨架、数据库、公共组件和本地依赖 |
| Phase 1 MVP 主链路 | Week 2-4 | 用户、商品、活动、抢购、订单和核销 |
| Phase 2 高并发与履约 | Week 5-6 | RabbitMQ、超时关闭、支付退款、实时状态 |
| Phase 3 运营治理增强 | Week 7-8 | 审核、举报、搜索、报表、风控和通知 |
| Phase 4 测试部署 | Week 9-10 | 自动化测试、压测、监控、部署和文档 |

### 1.2 里程碑

| 里程碑 | 时间 | 交付物 | 验收标准 |
| :--- | :--- | :--- | :--- |
| M1 基建就绪 | Week 1 | Spring Boot 项目、DDL、Redis/RabbitMQ 连接 | 项目可启动，数据库和中间件健康检查通过 |
| M2 MVP 完成 | Week 4 | 商品→活动→抢购→订单→核销链路 | 使用测试账号可完成完整交易 |
| M3 高并发可用 | Week 6 | 异步下单、超时释放和幂等机制 | 并发测试无负库存、无重复订单 |
| M4 运营可用 | Week 8 | 审核、报表、搜索、风控和通知 | 管理端可独立运营一次活动 |
| M5 发布就绪 | Week 10 | 测试报告、部署脚本和项目文档 | 核心 P0 用例通过，测试环境可演示 |

## 2. 任务依赖关系

```text
P0 基础设施
  B-01 项目骨架 → B-02 公共模块 → B-03 实体与枚举 → B-04 Mapper → B-05 Service/Controller
  B-06 MySQL/DDL ───────────────────────────────────────────────┘
  B-07 Redis ───────→ B-12 Redis Lua 与缓存规范 ──→ B-21 抢购接口
  B-08 RabbitMQ ────→ B-22 异步下单 ───────────────→ B-23 超时释放
  F-01 前端骨架 → F-02 组件规范 → F-03 API/权限封装

P1 MVP
  U-01 登录 → U-02 商品浏览 → O-01 商品维护 → A-01 审核
  O-02 活动配置 → U-06 预约/抽签 → U-07 抢购 → B-22 异步订单
  U-08 订单 → U-09 支付 → U-10 核销 → O-04 履约

P2 增强
  U-05 收藏提醒、U-11 评价举报、搜索、WebSocket、库存校准、风控、报表

P3 验收
  单元测试 → 集成测试 → 并发压测 → 安全检查 → Docker 部署 → 文档验收
```

## 5. Phase 2：高并发与履约增强（Week 5-6）

| ID | 任务 | 技术实现 | 工作量 | 验收标准 |
| :--- | :--- | :--- | :--- | :--- |

| B-22 | Redis Lua 原子扣减 | 一次完成活动状态、限购和库存校验 | 1.5 天 | 并发下库存不为负、用户不超购 |

### Phase 2 压测检查点

- 使用 JMeter 或 Gatling 模拟至少 1000 个抢购请求。
- 总库存 100 件时，最终成功订单不超过 100 件。
- 同一用户重复点击、重试消息、支付回调重复到达均不产生重复订单。
- RabbitMQ 停止消费后恢复，积压消息能够继续处理。

## 8. 数据库任务清单

### 核心表

`sys_user`、`sys_role`、`sys_operation_log`、`campus_pickup_point`、`product_category`、`product`、`product_sku`、`product_image`、`flash_activity`、`flash_activity_sku`、`activity_reservation`、`lottery_batch`、`lottery_result`、`inventory_log`、`trade_order`、`trade_order_item`、`payment_record`、`refund_record`、`pickup_verification`、`user_favorite`、`product_review`、`report_record`、`notice`、`user_message`。

### 必须建立的约束

- `activity_reservation(activity_id, user_id)` 唯一约束。
- `trade_order(request_no)`、`payment_record(order_id, payment_no)` 唯一约束。
- 商品、活动、订单状态使用枚举值和数据库注释说明。
- 订单金额使用 `DECIMAL(10,2)`，库存使用非负整数。
- 所有业务表包含 `created_at`、`updated_at`；关键表包含操作人和版本号。
