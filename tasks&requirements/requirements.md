# 校园文创限时抢购系统需求规格说明书

> 本文档采用用户故事和验收标准描述需求，适用于学生用户端、文创运营端和平台管理端。系统重点解决校园文创限量发售中的预约、抢购、库存一致性、订单超时和到店核销问题。

------

## 1. 文档说明

| 项目 | 信息 |
| :--- | :--- |
| 项目名称 | 校园文创限时抢购系统 |
| 目标用户 | 在校学生、校园文创运营人员、平台管理员 |
| 核心技术 | Spring Boot、MyBatis-Plus、MySQL、Redis、RabbitMQ |

## 2. 产品定位与边界

### 2.1 产品定位

平台面向校园场景销售校徽、校训、吉祥物、毕业纪念品、社团周边等文创商品。商品可以按普通商品、限时抢购、预约抽签和预售四种方式销售；用户线上下单后在校园自提点核销领取。

### 2.2 本期范围

- 账号注册、登录、校园身份信息维护
- 文创商品、分类、图片和库存管理
- 活动创建、预约、抽签和限时抢购
- Redis 预扣库存、RabbitMQ 异步下单、订单超时释放
- 模拟支付、退款、校园自提和二维码核销
- 收藏、评价、公告、站内消息
- 运营端商品/活动/订单管理
- 管理端用户、内容、风控和数据报表管理

### 2.3 暂不实现

- 真实银行卡、微信或支付宝资金清算
- 跨校物流和复杂售后仲裁
- 多商户分账和发票系统
- 真实短信、邮件等第三方资费服务（开发环境使用模拟适配器）

## 5. 用户故事清单

### 5.1 学生端

#### U-01 注册与登录

**作为** 成都信息工程大学学生，**我想要** 使用邮箱注册并登录，**以便于** 参与校园文创活动。

**验收标准**：

- 注册需要邮箱、昵称、密码和邮箱验证码，不单独设置用户名、学校或学号。
- 学校由平台固定为“成都信息工程大学”，邮箱是唯一登录标识，昵称用于页面和履约展示。
- 密码使用 BCrypt 加密存储，接口不返回密码或敏感字段。
- 登录成功返回 JWT，过期 token 不能访问需要认证的接口。
- 支持退出登录、刷新 token 和找回密码。
- 被禁用用户不能参与抢购，但可以查看公开公告。

**优先级**：P0

#### U-02 维护个人信息

**作为** 学生用户，**我想要** 编辑昵称并在订单中查看商家确定的领取点，**以便于** 准确领取商品。

**验收标准**：

- 可维护昵称，注册邮箱用于账号识别。
- 学生无需维护位置或默认领取点；订单展示商品发布时确定的启用领取点。
- 学校固定为“成都信息工程大学”，不采集学号。

**优先级**：P0

#### U-03 浏览和搜索文创商品

**作为** 学生用户，**我想要** 按分类、关键词、价格和发售方式浏览商品，**以便于** 找到感兴趣的校园文创。

**验收标准**：

- 支持关键词搜索商品名称、卖点和标签。
- 支持按分类、发售方式、价格区间和上架状态筛选。
- 支持分页、销量排序、最新发布排序和热门排序。
- 列表展示封面、名称、价格、库存状态、活动标签和发售时间。
- 使用 Elasticsearch 时搜索失败必须降级到 MySQL 查询。

**优先级**：P0

#### U-04 查看商品详情

**作为** 学生用户，**我想要** 查看商品图片、规格、材质、库存和领取规则，**以便于** 判断是否购买。

**验收标准**：

- 详情展示图集、规格、价格、限购数量、发售方式、活动时间和自提规则。
- 抢购商品展示未开始、进行中、已售罄或已结束状态。
- 展示当前用户是否预约、是否收藏以及可购买数量。
- 下架商品不可创建新订单，但历史订单仍可查看。

**优先级**：P0

#### U-05 收藏和活动提醒

**作为** 学生用户，**我想要** 收藏商品并订阅活动提醒，**以便于** 不错过限量发售。

**验收标准**：

- 收藏和取消收藏操作幂等，同一用户不能产生重复记录。
- 可在“我的收藏”查看商品当前状态。
- 预约活动开始前发送站内消息；消息发送通过 RabbitMQ 异步处理。
- 用户可以取消提醒，不影响已产生的订单。

**优先级**：P1

#### U-06 预约限时抢购活动

**作为** 学生用户，**我想要** 在活动开始前预约限时抢购，**以便于** 获得参加资格或接收开售提醒。

**验收标准**：

- 活动未开始且处于可预约状态时才能预约。
- 同一用户对同一活动只能预约一次，重复请求返回已有预约结果。
- 预约成功后展示预约编号和活动时间。
- 活动设置为抽签模式时，预约结果分为待抽签、获得资格和未中签。
- 抽签结果通过定时任务生成，并记录可追溯的抽签批次。

**优先级**：P0

#### U-07 参与限时抢购

**作为** 获得活动资格的学生，**我想要** 在开售时快速购买限量商品，**以便于** 获得校园限定文创。

**验收标准**：

- 活动未开始、已结束、未获得资格或用户已超过限购数量时，接口拒绝下单。
- 使用 Redis + Lua 脚本原子校验活动状态、用户限购和库存。
- 抢购请求成功后只返回排队/受理结果，不同步执行完整订单事务。
- RabbitMQ 消费者异步创建订单，消息重复投递不能生成重复订单。
- 库存不足时返回明确提示，不能出现负库存。
- 活动日志记录请求时间、用户、商品和处理结果。

**优先级**：P0

#### U-08 查看抢购结果和订单

**作为** 学生用户，**我想要** 查看抢购结果、订单状态和支付倒计时，**以便于** 及时完成购买。

**验收标准**：

- 订单状态至少包括待支付、已支付、待核销、已完成、已取消、退款中和已退款。
- 待支付订单显示剩余支付时间，超时自动关闭。
- 用户不能查看其他用户订单，也不能重复支付或重复取消。
- 订单列表支持按状态筛选和按创建时间排序。

**优先级**：P0

#### U-09 模拟支付和退款

**作为** 学生用户，**我想要** 使用测试支付完成付款或申请退款，**以便于** 完成完整交易流程。

**验收标准**：

- 支付接口使用幂等号，重复请求只产生一笔支付结果。
- 支付成功后通过 RabbitMQ 更新订单并确认库存状态。
- 未支付订单可以取消；已支付未核销订单可以按规则申请退款。
- 退款结果、时间和原因可在订单详情查看。

**优先级**：P0

#### U-10 校园自提与二维码核销

**作为** 已支付用户，**我想要** 查看提货码并在自提点核销，**以便于** 领取文创商品。

**验收标准**：

- 订单进入待核销后生成一次性提货码或二维码。
- 运营人员只能核销本人有权限的自提点订单。
- 同一订单重复核销必须被拒绝，并保留核销日志。
- 核销成功后订单变为已完成并通知用户。

**优先级**：P0

#### U-11 评价和举报

**作为** 已完成订单用户，**我想要** 评价商品并举报违规内容，**以便于** 反馈购买体验并维护平台秩序。

**验收标准**：

- 只有已完成订单且每个商品只能评价一次。
- 评价支持星级、文字和图片，图片上传到 MinIO。
- 用户可以举报商品、评价或用户，并填写举报理由。
- 被处理的举报展示处理结果，管理员操作写入审计日志。

**优先级**：P1

### 5.2 运营端

#### O-01 维护商品和规格

**作为** 文创运营人员，**我想要** 创建、编辑、上下架商品及规格，**以便于** 管理平台销售内容。

**验收标准**：

- 商品包含名称、分类、卖点、详情、图片、规格、售价、成本价和库存。
- 支持商品草稿、待审核、已上架、已下架状态。
- 商品编辑后可提交审核，审核通过才允许对外展示。
- 已产生订单的商品不能物理删除，只能下架。
- 库存变更记录操作人、变更数量、原因和时间。

**优先级**：P0

#### O-02 创建预约与抢购活动

**作为** 运营人员，**我想要** 配置活动时间、商品、库存、限购数量和活动规则，**以便于** 组织限量发售。

**验收标准**：

- 活动支持普通抢购、预约抽签和预售三种模式。
- 活动配置包含开始/结束时间、预约时间、活动库存、每人限购和支付时限，领取点继承自商品。
- 活动发布前校验商品已审核、库存充足、时间合法。
- 已有用户预约或订单的活动不能直接删除，只能终止并记录原因。
- 活动状态由未发布、预约中、待开始、进行中、已结束和已终止组成。

**优先级**：P0

#### O-03 管理活动库存和资格

**作为** 运营人员，**我想要** 查看活动库存、预约人数、抽签结果和抢购订单，**以便于** 及时处理异常。

**验收标准**：

- 展示数据库库存、Redis 可用库存、已预扣库存和已支付数量。
- 库存校准必须生成调整记录，不能静默覆盖。
- 抽签支持固定种子或批次号，结果可复核。
- 支持导出预约名单、中奖名单和订单列表。

**优先级**：P0

#### O-04 处理订单和自提核销

**作为** 运营人员，**我想要** 查询订单、确认退款和核销提货，**以便于** 完成线下履约。

**验收标准**：

- 可按活动、商品、订单状态、自提点和时间筛选订单。
- 支持扫码核销和订单号手工核销。
- 核销前显示商品、数量、用户和订单状态，核销后不可逆修改。
- 退款、补发和异常订单必须填写处理原因。

**优先级**：P0

### 5.3 管理端

#### A-01 管理员登录和权限

**作为** 平台管理员，**我想要** 通过独立后台登录并按角色授权，**以便于** 安全管理系统。

**验收标准**：

- 管理端独立登录入口，支持超级管理员、审核员、运营员角色。
- 使用 Spring Security + JWT 校验身份和权限。
- 不同角色不能调用未授权 API，所有敏感操作记录操作日志。

**优先级**：P0

#### A-02 审核商品与活动

**作为** 审核管理员，**我想要** 审核商品详情、活动规则和宣传图片，**以便于** 保证内容合规。

**验收标准**：

- 待审核列表展示提交人、内容摘要、提交时间和当前状态。
- 通过后商品/活动才可发布，驳回必须填写原因。
- 审核记录包含审核人、时间、结果和备注，支持查询。

**优先级**：P0

#### A-03 管理用户和举报

**作为** 管理员，**我想要** 管理用户状态、信用分和举报记录，**以便于** 处理刷单、恶意抢购和违规内容。

**验收标准**：

- 支持搜索用户、查看订单/预约/举报记录和禁用账号。
- 被禁用用户不能预约、抢购和支付，已有订单按规则处理。
- 举报支持待处理、处理中、已驳回和已完成状态。
- 信用分调整必须记录原因和操作人。

**优先级**：P1

#### A-04 数据看板和系统配置

**作为** 超级管理员，**我想要** 查看活动数据并调整平台参数，**以便于** 评估运营效果和控制抢购规则。

**验收标准**：

- 看板展示用户数、商品数、活动数、预约数、订单数、支付金额和核销率。
- 支持按日期、活动、商品和自提点统计。
- 可配置支付超时时间、默认限购数量、预约提前时间和风控阈值。
- 配置变更即时生效并记录审计日志。

**优先级**：P1

## 7. 非功能需求

| 类别 | 需求 | 验收标准 |
| :--- | :--- | :--- |
| 性能 | 普通查询接口 P95 ≤ 500ms | JMeter 压测验证 |
| 性能 | 抢购入口支持至少 1000 个并发请求 | 库存不为负、无重复订单 |
| 一致性 | Redis 预扣库存与 MySQL 最终库存可校准 | 异常消息可重试，存在补偿记录 |
| 可靠性 | RabbitMQ 消费失败可重试并进入死信队列 | 消息不静默丢失 |
| 安全 | 密码 BCrypt 存储，JWT 有效期可配置 | 数据库与接口安全测试通过 |
| 安全 | 防重复提交、限购、限流和权限校验 | 重复请求不重复下单 |
| 可用性 | 核心服务可用率 ≥ 99.5%（测试环境目标） | 健康检查和异常日志完整 |
| 数据 | 每日备份 MySQL，保留操作审计日志 | 可恢复最近一次备份 |
| 兼容性 | Chrome、Edge 最新两个稳定版本 | 核心流程无阻断 |
| 可维护性 | API 使用统一响应和错误码 | Knife4j 文档与代码同步 |

## 8. 核心业务状态

### 8.1 活动状态

`草稿 → 待审核 → 已发布 → 预约中 → 待开始 → 进行中 → 已结束/已终止`

### 8.2 订单状态

`待支付 → 已支付 → 待核销 → 已完成`

异常分支：`待支付 → 已取消`、`已支付 → 退款中 → 已退款`。

### 8.3 抢购一致性规则

- Redis Lua 脚本一次完成活动状态、用户限购和库存扣减。
- 抢购成功后写入唯一业务请求号，RabbitMQ 消费者按请求号幂等创建订单。
- 订单超时由延迟消息或定时任务关闭，并返还 Redis 预扣库存。
- 定时库存校准任务比较 Redis、订单和库存流水，异常进入人工处理队列。
